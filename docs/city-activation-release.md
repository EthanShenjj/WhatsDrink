# 城市激活上线与验证手册

## 本轮已落地的入口

- 空地图主按钮与「＋记录」菜单进入“点亮去过的城市”。系统行政区选择器只取省、市，不收集区县；照片、日期、定位均无需提供。
- 保存后跳到点亮地图并展开对应省份卡。省份卡列出已点亮城市，点城市或“补一处具体地点”进入预填省市的地点表单。
- 相同省市再次选择时打开已有城市记录。城市记录不计入地点、到访、地点年轮；未填日期的不进入时光日历。
- 省份卡可打开私人记忆图。默认只有省市和点亮数量；地点名称、一张记录照片、记录文字需用户逐项开启。用户点“保存到相册”后才请求相册权限。产品内没有直接分享入口。

## 上线前检查

1. 部署 `footprintMutation` 更新与新 `productEvents` 云函数；创建 `product_events` 集合，设置客户端读写均关闭。核对 `cloudbaserc.json` 与安全规则。
2. 用 iPhone、Android 真机分别检查：空地图不触发定位授权；省份边界点按、城市卡展示、城市选择器、相册保存与拒绝权限后的提示。
3. 依次检查无照片、无定位、日期留空、重复选择、北京/上海/天津/重庆、香港/澳门、断网保存后联网同步、旧足迹地点和到访统计不变。
4. 无网络或统计云函数不可用时仍应正常保存。确认云端 `product_events` 文档只有用户归属、动作和时间，没有地点、照片、文字或坐标。

## 三周自有账号内容草稿

发布前用真实产品操作录屏替换占位素材，避免展示他人的私人记录。每周两条，两个主题交替；引导用户搜索小程序名称，不要求用户转发记录。

| 周次 | 主题 | 标题草稿 | 内容骨架 |
| --- | --- | --- | --- |
| 1 | 不用照片，点亮去过的城市 | “没有旅行照片，也能把去过的城市点亮” | 展示空地图 → 选择一座城市 → 省份变亮；说明日期可留空。 |
| 1 | 给一座城市补回忆 | “先记得这座城，细节以后慢慢补” | 从省份卡点城市 → 预填省市 → 补一处地点，不上传照片。 |
| 2 | 不用照片，点亮去过的城市 | “90 秒做一张只属于自己的城市版图” | 展示一次选择多城后的点亮结果；说明无需定位。 |
| 2 | 给一座城市补回忆 | “突然想起那家店，把它加回地图里” | 从城市卡补地点，再在时光页回看；使用本人真实记录。 |
| 3 | 不用照片，点亮去过的城市 | “去过的城市，原来已经这么多了” | 展示省份卡与私人记忆图预览，说明需主动保存到相册。 |
| 3 | 给一座城市补回忆 | “不用把生活发出去，也能给它留个位置” | 展示私人记录、地点补充和回看，不出现公开分享按钮。 |

## 10 人独立操作

招募此前未使用过拾光迹的人。只给出任务“点亮一座你去过的城市”，不解释入口；从首次打开计时到省份卡出现。目标：至少 8/10 人在 90 秒内成功。观察误点、退出、授权困惑和是否理解“城市不等于具体地点”。若不足 8 人，优先修复入口与文案，再扩大投放。

## 首批 30–50 位外部新用户

以 `first_open` 为分母，统计首次点亮比例（有 `city_saved` 的用户占比）。30 天内回访行为看再次 `city_saved`、`place_added`、`old_record_opened` 任一动作的用户占比。另看 `city_picker_opened → city_saved`、`province_card_opened → place_added`、`province_card_opened → album_saved` 的流失位置。事件允许重复投递但云端以事件 ID 幂等写入；漏斗仅作本产品基线，结合访谈分析，不引用竞品自述数字作验收门槛。

操作时不要上传用户照片、记录文字或坐标到分析系统。三周内容发布、真人测试和 30 天回访观察需要在实际上线后执行，本仓库仅准备了代码、草稿和检查流程。
