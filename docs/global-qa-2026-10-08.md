# 全局测试、交互与设计走查（2026-10-08）

## 结论更正（同日再次复核）

此前把自动化全绿和若干页面的模拟器截图概括为“全量走查”，这个结论过宽。测试主要覆盖业务数据与常规路径，漏掉了原生 `cover-view` 快捷打卡按钮和两个底部弹层同时存在的状态；也没有逐一核对弹层在短屏、长地名和大字体下的可操作性。此前关于地图弹层“没有遮挡”的判断撤回。

本轮按“记录菜单打开、关闭动画、打卡弹层、附近有/无已保存地点、足迹详情、筛选”重新列出状态。记录菜单与无附近地点的打卡弹层已在 iPhone 16 模拟器截图核对，快捷打卡入口会卸载，关闭后恢复；附近有已保存地点的三按钮分支仍需真机实际数据复核。菜单行与打卡按钮已压缩，弹层高度设上限并允许内部滚动。模拟器还发现打卡流程重复调用 `showLoading` 的警告，现改为一次显示、一次关闭。

最新 `npm run check` 覆盖 43 个测试文件、263 项测试通过，包含弹层动画期间隐藏原生快捷入口和打卡加载提示配对的回归测试；`git diff --check` 通过。代码检查和模拟器走查均不能代替 iOS、Android 真机上对地图原生层、手势和安全区的最终验收。

## 本轮修复

1. 购买记录云端加载失败时，页头不再误报“共 0 条记录”，改为明确的失败态和重新加载入口。
2. “同步支付结果”只有在账户查询与订单列表刷新都成功时才显示成功；刷新失败时提示重试。
3. 会员等级权益标题改为“可用权益”；移除 Pro 卡片中免费版同样享有的“原始数据保留”，避免误认为该能力需要购买 Pro。

## 尚需真机与云端验证

- 开发者工具的全页面自动冒烟脚本被 AppID 信息请求 `ECONNRESET` 阻断；模拟器订单云请求显示 `Failed to fetch`。因此本轮不能证明所有页面的端到端云端行为。
- 需在支付配置和网络正常的真机上验证购买、到账、恢复查询、退款、临期与过期、Plus 升 Pro 后原 Plus 有效期保留，以及有多页订单时的加载和左滑隐藏。
- 需用有 Pro 权益且含一年、连续多年、无足迹三类数据的账号核对年度回顾与跨年对比的实际展示。

## 二次全局复核（同日）

- 重新执行项目结构校验、TypeScript 检查与完整测试：40 个测试文件、245 项测试通过；`git diff --check` 通过。
- 在 iPhone 16 模拟器中重新核对了“我的”合并资料与足迹统计卡、Plus 会员卡、会员页首屏的三级预览和权益对比、购买方案与最近购买。会员等级卡的文案与边界清晰，没有发现新的截断或遮挡。
- 购买记录实测首批 10 条、触底追加至 20 条，左滑可露出“隐藏”操作。末页第 21 条请求遇到云端 `Failed to fetch`，原界面只恢复“加载更多”按钮，用户无法判断失败；现已改为“加载失败，点击重试”，触底不再自动重复失败请求，增加了保留已加载记录和手动重试的回归测试。
- 购买记录未左滑时，红色隐藏操作底色在行边露出细线。已将行底色改为白色，隐藏按钮仍保持红色。该视觉修复编译后因 macOS 锁屏未能做最终截图确认。
- 云端未登录成功时，购买记录曾把本地缓存的最近几笔误当作完整分页列表，隐藏操作也可能只在本机生效。现改为显示云端连接失败；隐藏由云端确认后才清理本地缓存，增加断网与成功路径测试。
- 地图模拟器曾显示定位失败提示盖住南通聚合标记，已把重试提示上移至模式切换条下方。重新编译后的云初始化仍出现 `Failed to fetch`，未能在同一轮重现足迹标记完成截图确认。
- 支付、退款、恢复权益、订单末页成功加载和地图标记真机触点仍需网络正常的真机环境验证；本轮未发起实际交易或隐藏任何真实订单。

## 地图反馈复核与修复（同日）

- 上轮设计走查漏掉了三处真机问题：点亮地图只有省区着色，未强调已到访城市；原生 `show-location` 在未打卡时显示当前位置；地图浮层中的 SVG 快捷打卡图标未显示。原走查结论不能视为这些项目已通过。
- 点亮地图现依据已保存的到访记录生成城市标记，使用城市中心或已有足迹坐标定位；仅想去、定位结果及未保存打卡不生成标记。城市邻近时优先拟合已点亮城市，标记点击打开所属省区卡片。
- 已关闭原生位置点；获取当前位置仅移动视野。快捷打卡图标已换为本地 PNG，开发者工具 iPhone 16 模拟器截图确认可见。
- 项目结构、类型检查和自动化回归覆盖这些数据边界；地图原生标记在 iOS 与 Android 上的最终位置、相邻城市显示和点击仍需新版真机截图验收。
