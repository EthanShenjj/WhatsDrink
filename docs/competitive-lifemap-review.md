# LifeMap 截图对照：拾光迹的优化方向

基于用户提供的九张截图与本仓库当前实现。截图只能说明竞品展示了哪些界面，不能证明其真实留存、转化或性能。

## 从截图看到的有效做法

| 竞品画面 | 用户价值 | 拾光迹当前情况 | 建议 |
| --- | --- | --- | --- |
| 点亮模式里省份按轮廓着色 | 每记录一处就看见版图变化 | 原先只有省份数字、名单和城市成长圆 | 已加入中国省级区块填色和点击地区回忆卡 |
| 日期、类型、心情、照片、文字放在同一记录流程 | 减少理解成本 | 表单核心字段清晰，但心情、类别与短记在“更多设置”内 | 先观察用户是否想用这些字段；若使用率高，将“心情＋一句话”上提为轻量快捷记录 |
| 地图与时间轴并列呈现 | 能按时间重访同一地区 | 我们已有时光日历、时间线和地点年轮 | 在地区卡增加“按时间回看”入口，保持地图与时光双向联通 |
| 地区颜色、心情符号和照片共同表达记忆 | 地点不再只是坐标 | 我们已有足迹详情、Lumi、照片、心情 | 地图保持克制，情绪和照片重点放进点按后的地区卡 |

## 页面优化优先级

### P0：让地图上的奖励立即可见

- 已完成：点亮模式中，已到访的中国省级行政区按边界着色；点地图或上方省份标签可查看该省的地点数、到访次数与最近三条足迹。有城市数据时也展示城市数。原有记录若缺少省份字段，可根据已保存的地图坐标归入对应省区。
- 已完成：把原先大块统计面板收成紧凑浮层，为地图留更多空间；选中地区后再展开记忆卡。
- 待真机验收：检查腾讯原生地图多边形的边界对齐、Android/iPhone 的层级与点按坐标，尤其是香港、澳门和岛屿。边界是简化展示，不适合精确行政区判定。

### P1：缩短第一次记录路径

- 默认只要求“地点＋日期”，可附照片；保存后立刻进入有反馈的点亮地图。已有表单基本具备这条路径。
- 做一轮 5 人观察：从首次打开到保存第一条足迹，记录完成率、用时和卡住的位置。若多数人主动寻找心情或短记，再把它们从“更多设置”移到主流程。
- 把“记录后能得到什么”写进空态：地图会点亮，未来会在时光页重遇，而非仅提示新增一条数据。

### P1：提升回看频率

- 从省份卡进入该地区的时光回顾，可按年/月看去过的地点；现在先提供最近三条可点按的回忆。
- 将“同一地点又来了一次”的地点年轮、往年今日、时光胶囊串成一个有节奏的私密回忆体验。先验证时光页旧记录打开率，再增加提醒，避免为了活跃而打扰用户。

### P2：把记录做成可保存的私人作品

- 用户明确要求现阶段不做直接分享。可让用户主动生成“本月足迹 / 城市记忆”图片并保存到相册，用于自己留存；不设置分享按钮，也不把传播作为这个功能的目标。
- 图片生成前可选择隐藏精确地址、私人文字和照片；默认只展示城市级信息，保存前提供预览。保存到相册由用户主动触发，权限被拒绝时保留站内查看入口。

## 差异化定位

**拾光迹 = 把日常地点留成私人记忆，而不只是旅行打卡。**

竞品截图的主线是“去过哪里、点亮多少地区”。拾光迹可以把竞争重点放在“这个地方与我发生了什么”：同一地点多次到访的变化、普通日常的照片与情绪、往年今日重逢、写给未来的胶囊，以及由 Lumi 陪伴但不替用户编造记忆。省份点亮提供即时成就感；长期留存来自可回看的真实生活。

品牌表达也应统一使用“拾光迹 / SHIGUANGJI”。仓库中与竞品同名的 LifeMap 装饰文案已替换，避免在页面上弱化自己的识别度。

## 验证指标

| 目标 | 建议观察 |
| --- | --- |
| 首次价值是否可感知 | 打开地图 → 开始记录 → 保存首条足迹的完成率与耗时 |
| 点亮是否被理解 | 保存后进入点亮模式的比例、地区区块点按率、地区卡打开率 |
| 回忆是否带来复访 | 时光页旧记录打开率、7/30 日回访率、同一地点二次记录率 |
| 私人作品是否有价值 | 记忆图生成率、保存到相册成功率、作品页再次打开率；因隐私顾虑取消保存的比例 |

行政区着色使用 [China-GeoData](https://github.com/Supeset/China-GeoData) 的省级 GeoJSON 经简化生成。微信地图的多边形能力见 [TencentLBS 小程序地图组件指南](https://github.com/TencentLBS/tencentmap-miniprogram-skill/blob/main/references/map_component_guide.md)。
