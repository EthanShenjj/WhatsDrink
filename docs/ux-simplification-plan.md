# 拾光迹体验减负方案

> 2026-10-01 · P0 已实施，P1 待后续排期

## 1. 目标与判断

让第一次打开小程序的用户迅速理解三件事：**地图看去过和想去的地点、记录入口添加地点、时光回看过去**。已有页面的视觉语言比较一致；当前负担集中在首屏同时出现多个任务、相同内容跨页重复、图标与实际操作不一致。

本方案基于当前页面代码及 `output/multi-device/iphone/` 中 2026-09-30 的截图。截图可用于判断层级，最终排版仍需用最新构建和真机确认。方案是产品判断，尚未经过用户测试。

### 页面职责

| 页面 | 用户来这里做什么 | 首屏应该看到什么 |
| --- | --- | --- |
| 地图 | 看足迹、切换想去、添加地点 | 地图、清楚标注的模式、一个记录主入口 |
| 时光 | 找回和浏览记录 | 最近回忆、日历或时间线 |
| 我的 | 看个人积累、管理账户与扩展能力 | 个人资料、足迹概览、次级功能入口 |

保留现有的三个内容主导航及中间“记录”按钮。新功能应先找到上述职责归属，再决定是否需要露出在首屏。

### 命名体系

| 对象 | 统一名称 | 使用规则 |
| --- | --- | --- |
| 产品 | 拾光迹 | 只用于产品品牌与版本信息 |
| 陪伴角色 | Lumi | 成长、颜色、主题和陪伴文案统一使用 |
| 用户 | 用户昵称 / 你好 | 不再为用户创造“拾光者”身份名称 |
| 付费能力 | 会员 | 日常入口统一称“会员”，只在购买页与已购状态中区分 Plus / Pro |
| 成长计量 | 成长值 | 替代“碎片”等额外概念 |

旧默认昵称会在本地和云端读取时迁移为空值，用户已主动设置的昵称保持不变；支付商品 ID 与权益字段保持原值。

## 2. 第一阶段：主页面减负（P0）

实施状态：已完成代码调整。地图、时光和“我的”的具体改动如下；真机视觉回归仍按第 5 节执行。

### 地图：一条记录路径，一个次级工具区

当前首屏同时有“足迹 / 想去 / 点亮”、成长状态、搜索 / 筛选 / 设置、当前位置打卡、记忆提示和底部“记录”。其中右侧“搜索”实际调用 `wx.chooseLocation`，选点后直接进入新增记录；用户可能以为它是在搜索已有足迹。

1. 中间“记录”保持唯一常驻新增入口。点击后给出三个动作：**当前位置打卡、手动记录足迹、添加想去**。复用现有打卡和表单流程，不改变数据含义。移除地图上常驻的大尺寸“当前位置打卡”卡片。
2. 移除地图右侧“搜索”悬浮按钮；在记录动作中保留“选择地点”能力。以后若开发真正的已有足迹搜索，再使用“搜索”命名。
3. 地图右侧仅保留“筛选”；“地图设置”放在“我的”菜单中，保持原有入口。筛选激活时继续显示状态与一键清除。
4. 顶部模式使用清楚的文字“足迹 / 想去 / 点亮”，避免只有闪光图标代表“点亮”。顶部成长状态移到“我的”。
5. “今日掉落”统一在“时光”呈现；附近旧记忆只有在确实与当前位置有关且用户主动获取位置后，才以轻量提示出现，不常驻占用地图底部。
6. 无记录时保留一个指向“记录”的空态；有记录时让地图标记成为视觉主角。待补位置面板保留，但默认折叠为一行提示。

**地图首屏草图：**

```text
足迹  想去  点亮                       筛选

                 地图与地点标记

地图          时光          ＋记录          我的
```

### 时光：让回忆浏览先出现

1. 移除顶部“本周 Lumi 状态”大卡；成长详情只从“我的”进入。
2. 有“今日掉落”时保留一张回忆卡；多条内容横向滑动或进入完整列表。无内容时不显示该区块。
3. 将“日历 / 时间线”切换及当前内容上移，使首屏能看到浏览入口和至少一部分记录。保留顶部“时光胶囊”入口，同时移除“我的”菜单中的重复入口。
4. 空日历和空时间线都提供同一条“记录第一处足迹”行动，避免空态之间出现不同说法。

### 我的：先展示用户积累，再展示扩展能力

建议顺序：**简洁资料行 → 足迹版图统计 → Lumi 成长入口 → 想去与计划 / 设置等菜单 → 会员入口**。已付费用户的权益状态可在会员入口内直接显示。

1. 把足迹统计移到会员与成长之前；保留“地点 / 城市 / 想去”三项主数字，照片、省份、愿望实现放入详情或折叠区。
2. 成长大卡改为一行摘要，点击进入完整成长页；相同周状态不再横跨地图、时光、我的三处首屏。
3. 会员保留一个清晰入口。合并当前会员大卡与菜单里的重复购买入口，位置放在主数据之后；具体套餐只在购买页区分 Plus / Pro。
4. 菜单只保留每个功能的一处入口；“时光胶囊”归“时光”，“地图设置”归“我的”。

## 3. 第二阶段：次级页面整理（P1）

| 页面 | 调整 |
| --- | --- |
| 记录表单 | 现有“地点 / 日期 / 照片 + 更多设置”分层合理，保留。将“今天 / 昨天”快捷日期按使用情况决定是否保留两项；保存按钮始终可见并清楚说明缺失的必填项。 |
| 成长页 | 首屏只呈现当前状态与下一个目标。颜色、表情、隐藏状态、图标主题归入“收藏与装扮”区，可逐项展开。会员方案放在页面后段，并保留已开通状态。 |
| 攻略页 | 标题改为“想去与计划”，与页面实际内容一致。想去和旅行计划都为空时，合成一个空态和一个“添加想去”按钮；已有心愿后再展示计划创建引导。 |
| 会员页 | 保持独立购买页；从主导航首屏撤下促销卡后，核对免费与已付费用户的入口文案、剩余天数和购买记录是否仍易找到。 |

## 4. 交互与视觉规则

- 每个主页面首屏只突出一个主要动作。辅助动作使用文字或清楚标签；不要让多个圆形图标要求用户猜含义。
- 同一概念只在一个页面承担主要展示：成长在“我的”，回忆在“时光”，地点在“地图”。其他页面仅在确有场景价值时提供小型跳转。
- 空态只提供一个下一步，不同时展示“去地图”“去记录”“去攻略”等多个相近按钮。
- 新能力优先放进对应详情页或菜单，再根据实际使用数据决定是否升到首屏。
- 保持现有隐私设置、数据查看与编辑、付费权益和记录内容的可达性；页面降权不应让已拥有的内容难以找回。

## 5. 实施顺序与验收

| 顺序 | 改动 | 验收方式 |
| --- | --- | --- |
| P0-1 | 合并地图新增入口，修正“搜索”误导，收起地图非核心浮层 | 记录足迹、当前位置打卡、添加想去均能完成；地图标记、筛选、点亮仍可达 |
| P0-2 | 时光移除成长大卡，回忆与日历上移 | 首屏可见浏览入口；今日掉落和时光胶囊仍可进入 |
| P0-3 | 我的重排、去重会员和胶囊入口 | 足迹统计先于会员；成长、购买记录、地图设置均可找到 |
| P1 | 整理成长、攻略和表单细节 | 空态与已有数据两种状态均无死入口或重复引导 |

实现后先用最新构建检查 iPhone、Android 和窄屏设备，重点检查地图原生组件上的浮层、底部安全区、长文案与字号。随后找至少 5 位未参与开发的人，各自完成“新增足迹、当前位置打卡、添加想去、找回旧记录、找到成长与购买记录”五个任务，记录完成率、耗时、误点和他们对页面用途的描述。此轮先建立基线；若有人找不到核心任务入口，继续调整文案和位置再上线。

上线后比较改版前后同来源用户的“打开地图 → 开始记录 → 保存成功”漏斗、时光页旧记录打开率、想去创建率，以及会员页到达与购买转化。地图首屏不再展示会员卡，**会员曝光量下降本身不算失败**；应看真正有购买意图的用户能否顺利找到并完成购买。
