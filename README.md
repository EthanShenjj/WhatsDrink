# 拾光迹 Shiguangji

把走过的地方，留成一张会长大的地图。

拾光迹是一款以地图为主界面的微信小程序，把"地点 + 时间 + 照片 + 心情"组织成长期个人记忆资产。区别于旅行攻略和地图打卡，拾光迹首先是一款私人记忆产品——即使没有长途旅行，也能记录周末散步、第一次约会、家门口的老店、常去的公园等普通但重要的时刻。

## 已实现

- 地图三模式：去过（回顾已发生的生活）/ 想去（保存未来期待）/ 点亮（看到足迹版图扩张）
- v1.0 城市成长：按城市内到访的唯一地点数计算 1/3/10 地点的三级成长，并在地图和点亮面板呈现
- 地点年轮：同一地点的多次到访保留独立记录，在详情页按时间串联，可对照初访与最近一次、标记重要时刻并再次到访
- 今日记忆浮现：时光页优先显示往年今日，再从近 30 天回忆中按日期稳定抽取，最多 3 条；地图的附近回忆仅在主动定位时触发
- 足迹记录：地点、日期、照片（0~9 张）、心情、类别、标签、短记、标记样式、可见性
- 时光日历：月历视图按日期聚合足迹与照片，点击查看当日地点卡流
- 筛选系统：时间、地区、类别、心情多维度组合筛选，以 Chips 显示当前条件
- 点亮统计：去过的国家/地区、省/州、城市、唯一地点数；点亮页以统计和地区列表呈现
- 心愿种子 → 愿望开花：实现愿望时保留原始心愿及创建时间，另建独立到访记录，并统计已实现愿望
- AI 小拾助手：当前用关键词规则提取文本草稿，图片作为附件；用户确认后才创建足迹（真正的 AI / 图片识别待接入）
- 旅行攻略：从想去清单选择地点，按天安排并保存为计划（智能路线优化待接入）
- 时光胶囊：选择足迹或新建文字/照片，设置未来解锁日期；配置订阅模板并取得授权后可发送提醒
- 微信登录 + 云端同步；云环境不可用时使用本地存储，随后不会自动合并两端数据
- 拾光+ 虚拟支付：31 天卡 / 372 天卡、7 天试用、购买记录、幂等发货、查单补发与退款权益回收；真实扣款需按部署文档配置微信后台与云函数密钥
- 隐私优先：足迹仅用于用户自己的记录与回顾，不提供公开发布入口

## 本地体验

1. 安装依赖：

   ```bash
   npm install
   ```

2. 在微信开发者工具中导入仓库根目录。
3. 选择"游客 AppID"可使用本地存储体验；首次打开后在"工具 → 构建 npm"生成 `miniprogram_npm`。
4. 运行检查：

   ```bash
   npm run check
   ```

## 接入真实小程序与云开发

1. 将 [project.config.json](project.config.json) 的 `appid` 换为真实 AppID。
2. 创建云开发环境，把环境 ID 写入 `miniprogram/services/config.ts` 的 `CLOUD_ENV_ID`。
3. 按[数据库结构](docs/cloudbase-database-schema.md)创建五个集合并配置索引。
4. 在开发者工具中分别上传并部署 `cloudfunctions/` 下九个云函数，选择"云端安装依赖"；同时上传 `sendCapsuleReminder` 的触发器。虚拟支付额外配置见[虚拟支付部署说明](docs/virtual-payment-setup.md)。
5. 按 [CloudBase 安全规则](docs/cloudbase-security-rules.md) 配置数据库、云存储和云函数权限。
6. 在小程序管理后台填写用户隐私保护指引，说明位置、相册/相机和云存储用途。
7. 如需时光胶囊订阅消息，在微信公众平台选择模板，把模板 ID 写入 `miniprogram/services/config.ts` 的 `CAPSULE_TEMPLATE_ID`，并给 `sendCapsuleReminder` 配置 `CAPSULE_TEMPLATE_ID` 环境变量。

## 当前验收边界

- 地图的城市成长目前以圆形视觉表达，省/市多边形填充尚需行政区边界数据与设备端地图验证。
- 首页默认视角落在中国附近，但原生地图可浏览海外；没有足迹时不会自动请求位置。底图本身由微信地图组件提供，当前使用默认样式。若已开通腾讯位置服务个性化地图，在 `miniprogram/services/config.ts` 填入 `MAP_STYLE_SUBKEY`，并把 `MAP_STYLE_IDS` 对应到已发布的「清爽 / 手账 / 夜间」样式编号。个性化样式可能需要在微信公众平台购买和配置，开发者工具也不能代替真机样式验收。
- 大数据量地图仍需视野范围查询、分批加载和低端机性能验收；当前云端按 100 条分批拉取全量记录后由客户端聚合，尚未完成 PRD A08 的千点性能目标。
- 愿望实现流程已做独立记录与幂等处理，但云端和本地存储不自动合并，真实环境中还需验证异常中断后的恢复。
- AI 草稿、图片识别、路线优化属于 P1，当前实现是可确认的规则草稿与手动排程。
- 胶囊订阅提醒需要真实 AppID、云环境关联、模板及云函数部署；本地检查不能代替真机验收。

## 信息架构

| 一级入口 | 职责 | 核心内容 |
|---------|------|---------|
| 地图 | 主场景 | 去过 / 想去 / 点亮三模式、筛选、地点卡 |
| 时光 | 回忆浏览 | 今日记忆浮现、日历、时间线、照片流 |
| 我的 | 资产与设置 | 统计、成长计划、探索与轻攻略入口、隐私与个人设置 |

全局入口：底部中心「＋」可新增足迹或心愿；「探索与轻攻略」作为 P1 从「我的」进入；浮动「AI 小拾」入口降低填写成本。

## 数据模型

核心对象 `Footprint`：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| footprint_id | string | 是 | 足迹唯一 ID |
| status | enum | 是 | visited / wishlist / fulfilled；fulfilled 心愿与 visited 到访是两条独立记录 |
| place_id | string | 否 | 同一地点的稳定分组键，用于地点年轮及城市成长 |
| wish_id / fulfilled_visit_id | string | 否 | 已实现心愿与独立到访记录之间的双向关联 |
| poi_name | string | 是 | 地点名 |
| lat / lng | number | 否 | 地图坐标；手动记录可稍后补充，未标注位置会显示在地图卡片列表 |
| visit_date | date | visited 必填 | 访问日期，默认今天 |
| photos | array | 否 | 0~9 张 |
| mood | string | 否 | 心情标签 |
| category | string | 否 | 地点类别 |
| tags | array | 否 | 用户标签 |
| note | text | 否 | 短记 |
| source | enum | 是 | manual / ai / import |

## 产品体验原则

1. 先记录，再完善——任何时候都能用最少字段保存
2. 地图不是数据表——首先让用户"看见人生"
3. 普通一天也值得——不只服务旅行打卡
4. 默认保护隐私——个人足迹只用于用户自己的记录与回顾

> "记录一个地点"只是功能；"把走过的地方，留成一张会长大的地图"才是产品感受。
